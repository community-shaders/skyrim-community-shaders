# 中云细节侵蚀与条带形态研究

下面保留最初研究的基线和结论。1.3.1 对用户截图暴露问题的复核、修正及验证限制见文末；最初的合成波列实验不足以验证真实条带分布。

2026-11-08。对象是现有独立中云层及用户提供的五张照片，观看条件为地面和山顶。目标是保留低云 NDF 输入、共享噪声与独立中云步进，以可控成本改善 Ac 的细碎轮廓和 As／Ac 的条带。本轮没有修改或部署渲染实现。

**结论：目前缺少的首先是轮廓侵蚀和有方向的形态控制，不能只归因于噪声不够细。二维输入足以生成条带，也能侵蚀云层表面；三维噪声进一步提供高度之间独立的凹凸。照片和离线对照尚不足以证明必须全面改用低云密度算法，也不能证明加一次三维噪声就能获得低云的细节质量。**

推荐保留 HP 式薄层载体，把条带用于覆盖、厚度和高度的独立调制；细节比较应围绕“二维表面侵蚀”和“共享三维噪声侵蚀薄层”展开。两者都必须在同一光学厚度、相同采样预算下检验，光照通过位置相关的密度／光学厚度查询读取结果。

## 当前代码与 HP 的实际能力

当前中云已经是被 raymarch 的三维密度场，只是其形态受二维柱状模型约束。它不是一张简单贴在天空上的图片。忽略曲率、单位换算后，可写成：

```text
M(x,y) = weatherDensity * cellFactor
E(x,y) = wisp(x,y)^2 * wispStrength * type
h = (z - bottom(x,y)) / (top(x,y) - bottom(x,y))
sigma(x,y,z) = densityScale * max(M(x,y) - E(x,y), 0) * P(h)
```

`P` 是上下平滑边缘的高度剖面。`cell` 同时影响密度和云顶，`wisp` 则在乘高度剖面之前扣除密度。

**因此，当前 wisp 可以让整根柱变稀、消失，也可以形成平面上的碎边；它不会在一根仍然非空的柱中单独挖出云底／云顶凹凸。** 将 wisp 频率调高会增加平面碎纹，无法独立增加高度方向结构。源码见 [MiddleCloudColumn](<D:/lyj/codes/git/skyrim-community-shaders/features/Physical Sky/Shaders/PhysicalSky/MidCloud.hlsli:70>)。

| 项目         | 当前实现                                                   | 本地 HP 阅读版                                         |
| ------------ | ---------------------------------------------------------- | ------------------------------------------------------ |
| 中云细节输入 | 2D cell、warp、wisp                                        | 同样是 2D，不采样 3D 体积噪声                          |
| 非等比缩放   | cell 为标量；wisp 固定为 cell 的 4 倍；warp 的 UV 频率固定 | cell、wisp、warp 各有独立 `float2` scale，可非等比拉伸 |
| warp 输入    | 同一单通道噪声两次偏移采样                                 | 一次 RG 采样                                           |
| cell 响应    | 固定平方                                                   | 可调幂                                                 |
| As 细节      | 有单独 As cell 强度；type=0 时 wisp 侵蚀为零               | wisp 同样乘 type；这不是 As 必须无细节的依据           |
| 高度与密度   | 覆盖同时驱动 bottom、top、density                          | 也有覆盖驱动，但底部幅度、阈值等控制更多               |
| 视线积分     | 柱状高度剖面分段解析积分，并用密度质心定位光照             | 中云独立点采样步进                                     |
| 自阴影       | 3 km 上限，固定 8 段，段内积分高度剖面                     | 3 km 上限，`_NumLightSteps` 可配，中点密度采样         |

HP 的直接依据是 [EvaluateHighCloudDensity](D:/lyj/codes/git/HPVolumeCloud/VolumetricClouds.hlsl:621) 和 [EvaluateSunLuminanceHighCloud](D:/lyj/codes/git/HPVolumeCloud/VolumetricClouds.hlsl:835)。该文件明确是 GitHub 阅读版，部分 HDRP 函数省略，不能作为可运行的完整 HP 画质基准。**“固定八次光步”是我们当前的选择，不是 HP 算法规定。**

HP 的二维缩放能生成拉长的云块，方向纹理也能产生条带；它没有在上述代码中提供独立的波列间距、云底起伏等完整控制。不能从这些参数推断它已经复现了图 4 的连续云幕。

当前静态中云图的 R 覆盖、G 类型、B 混合权重可以画出条带覆盖，但生成后只有 512² 的天气场。即使输入高分辨率 DDS，细节也受这一步限制。覆盖还被固定映射为：

```text
q = coverage^heightPower
bottom = 0.2 * (1 - q)
top = 0.2 + 0.8 * q
density = smoothstep(0.15, 0.65, coverage)
```

见 [天气生成](<D:/lyj/codes/git/skyrim-community-shaders/features/Physical Sky/Shaders/PhysicalSky/MidCloudGenerate.cs.hlsl:71>)。因此它能表达“条纹覆盖连带改变厚度”，但不能独立表达“覆盖和厚度不变，整层上下起伏”。现有 RGBA 中已经存储 density 加权的 bottom、top、type，内部载体有能力承载不同的高度关系，不需要为此改变低云 NDF 格式。

## 从 HFW 借鉴什么

HFW 普通云的二维 NDF 管宏观高度、覆盖和类型，最终细节来自真正依赖高度的三维噪声。它将噪声作为阈值侵蚀高度剖面与覆盖的乘积，再施加非线性密度响应。当前低云也有相应路径。

这与“二维 wisp 先减密度，再乘平滑剖面”不同：噪声能够改变等密度轮廓，在云底、侧面和云顶产生不同的凹凸。HFW 的密度响应也参与实体感，不能把全部画质差异归功于纹理维度，或仅复制一个幂指数。

依据为本地 [普通云噪声与密度](D:/lyj/soft/horizonwestforbidden/Clouds/handwritten/Common/MainCloudDensity.hlsli:162)、本项目 [CloudNoise](<D:/lyj/codes/git/skyrim-community-shaders/features/Physical Sky/Shaders/PhysicalSky/CloudNoise.hlsli:28>)，以及 [Nubis Evolved](https://www.guerrilla-games.com/read/nubis-evolved) 讲义物理页 29、33、34。讲义页 97–105 的 Envelope 模型还说明：上下高度面限定的薄层，可以结合三维侵蚀；**保留二维天气载体与使用三维细节并不冲突。** Envelope 的具体剖面和光照不能直接当作中云参数。

本项目普通形状体与可选 `NoiseVoxel` 的 RGBA 通道语义不同。若复用现有三维资源，应沿用对应资源的重建约定；不能假定所有体纹理的 A 都是同一种侵蚀量。这里只借鉴普通云和薄层模型，不引入 storm、supercell 或 Cb。

## 离线对照结果

实验文件保存在 [研究目录](D:/lyj/codes/git/skyrim-community-shaders/build/middle-cloud-research)。[study.py](D:/lyj/codes/git/skyrim-community-shaders/build/middle-cloud-research/study.py) 可重复生成图表与 [metrics.json](D:/lyj/codes/git/skyrim-community-shaders/build/middle-cloud-research/metrics.json)。它们使用固定种子的合成场，检验表示与积分行为；不是游戏截图，也没有复现 HP／HFW 的完整光照。

### 轮廓侵蚀和纹理维度是两件事

在相同宏观上下界、相同平均垂直光学厚度 1.3 下比较四种场：

```text
A  max(M - a*E(x,y), 0) * P(h)             当前侵蚀顺序的简化模型
B  max(M*P(h) - a*E(x,y), 0)               二维噪声侵蚀高度剖面
C  max(M*P(h) - a*E(x+s*z,y), 0)           随高度平移的二维噪声
D  max(M*P(h) - a*E(x,y,z), 0)             三维噪声侵蚀高度剖面
```

每种场只用一个全局倍率匹配平均光学厚度，不逐像素匹配。对照包含垂直截面、90° 和 20° 仰角的透射，以及同一简化光照下的图像。

- **B 已能改变上下轮廓。** 所以“当前轮廓不够碎”不等于“必须 3D”。另一种二维方案是用细节分别位移 bottom／top，继续保留柱状剖面。
- **C 仍存在挤出方向。** 随高度平移可以打破垂直贯穿纹，但不能提供任意方向的体积结构；本例的投影还会平均掉一部分细节。
- **D 有高度独立的凹凸，却不自动更锐利。** 本例中多层叠加会填补一些贯通孔洞，局部投影反而更平滑。只有同时选择合适的频率、侵蚀幅度和密度响应，才能把新增结构变为所需视觉。
- 本组使用平滑随机场，不足以评判实际 Alligator／Worley 资源能否复现照片中的细碎边缘；它验证的是上述表示差异。

图：[密度与透射对照](D:/lyj/codes/git/skyrim-community-shaders/build/middle-cloud-research/shape-comparison.png)、[简化光照对照](D:/lyj/codes/git/skyrim-community-shaders/build/middle-cloud-research/lighting-comparison.png)。

### 条带至少需要区分三种调制

以相同方向、480 m 周期及缓慢弯曲的合成波列，对比覆盖、厚度、整层高度位移；三者平均垂直光学厚度均为 1.8。

| 调制         | 垂直光学厚度范围 | 主要结果                                           |
| ------------ | ---------------: | -------------------------------------------------- |
| 覆盖         |           0–3.60 | 产生透天间隙，适合图 3、5 的组织方式               |
| 厚度         |        0.96–2.64 | 不露天也能产生厚薄差异                             |
| 等厚整层位移 |        始终 1.80 | 正上方透射不变，但斜向太阳光路变化，仍能产生明暗带 |

最后一种在 20° 太阳仰角下，云底附近的直接光透射第 5–95 百分位约为 0.0035–0.0316。这个差异来自实际积分路径，不是给条带涂颜色。因此，“只用本地垂直光学厚度算全部光照”会遗漏一类有用的条带形态；斜向光学厚度查询能够识别它。

### 加入细节后不能直接沿用解析柱积分

当前 `MiddleCloudSegment` 对一个固定 XY 柱的高度剖面做解析积分，薄柱不会轻易漏采。但沿斜向光线仍会跨越不同柱；这个积分从来不是对任意 XY 变化精确。若增加 B／C／D 类侵蚀，原来的解析函数也不再给出最终密度积分；用它作为宏观包络仍然有价值。

采样实验采用 669 m 层厚、31.785 km 天气尺度，按当前步长公式计算步数。在三档噪声周期、三档仰角、128 条射线、32 个采样相位上，用 0.5 m 积分作为参照。下表取基周期 64 m、最细一档 16 m 的合成三维阈值场：

| 仰角 | 当前公式步数 | 每步 1 次密度查询 | 每步 2 次 | 每步 4 次 |
| ---- | -----------: | ----------------: | --------: | --------: |
| 90°  |           16 |             4.29% |     0.58% |     0.14% |
| 30°  |           16 |             3.23% |     1.18% |     0.55% |
| 10°  |           31 |             1.69% |     1.21% |     1.05% |

数值为光学厚度 RMSE／平均参考厚度。0.5 m 与 1 m 参考的最大差异小于 0.0037%。实验采用平面层、未过滤的最终密度点积分，不包含球面远景、当前解析段积分、时域重建或实际噪声资产，因此这些数值不是游戏误差或帧率预测。

它说明细节周期、角度与采样相位会共同决定误差；更大的周期也可能因步长对齐出现更大误差。**增加噪声以后，“步数没变”只能证明查询预算相近，不能证明结果稳定。** 更细密度查询也不必逐次运行完整光照，可在一个宏观段内先积累光学厚度与质心；是否足够要用实际视线和光照共同验证。

图：[采样误差对照](D:/lyj/codes/git/skyrim-community-shaders/build/middle-cloud-research/sampling-comparison.png)。

### 噪声 mip 不能保证保持光学厚度

对 `rho=max(0.4-0.6*N,0)`，一个覆盖两个等权样本 `N=0,1` 的 footprint：

- 先计算密度再平均，结果为 0.2。
- 先平均噪声再计算密度，结果为 0.1。
- 取路长系数 4，平均透射为 0.60095，而平均密度对应的透射为 0.44933。

因此噪声过滤、非线性侵蚀和透射平均不能交换顺序。远景只调大 noise mip，可能改变覆盖、厚度或环境光，而不仅仅减少细节。例子用于证明机制，不代表实际噪声有 50% 的平均密度误差。

视线的像素 footprint 和沿 ray 的段长度也应分别考虑。此前用段的水平长度做各向同性 mip 会抹掉垂直于 ray 的细节；只用像素 footprint 则不能解决沿 ray 的漏采。新方案需要在段内积分或沿 ray 过滤，不能把原先的过度模糊重新加回来。

## 建议的表示与成本边界

### 条带保留在二维天气载体中

条带方向、间距和缓慢弯曲属于宏观形态。可用旋转后的非等比噪声，或被低频噪声扰动的波列相位生成。普通拉伸噪声适合不规则长条；若目标是图 3、5 那种较连贯的间距，显式相位更容易控制。幅度和弯曲应缓慢变化，避免整片天空像规则正弦光栅。无需流体或重力波模拟。

同一个条带信号可以分别改变覆盖、厚度和高度位移，但三种幅度不能被硬性绑在一起。静态贴图继续作为场景输入；现有 R/G/B 语义保持不变，内部生成器可结合场景形态参数产生 bottom／top。宏观条带可以在已有中云天气图生成阶段计算，细碎侵蚀继续运行时求值，避免被 512² 天气图压平。

As／Ac 控制平滑层到云团的连续变化，条带控制空间组织。As 可以保持较弱侵蚀，但不应把所有细节硬乘 type 清零。条带与细节也不应共用一个非等比缩放，否则细碎云团会一起变成长丝。

### 两种细节方案的取舍

| 方案                       | 对当前目标的价值                                           | 真实代价／限制                                                                         |
| -------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 只增强当前 wisp            | 增加平面裂口和纹理                                         | 仍是整柱密度削减，不能独立改善底面凹凸                                                 |
| 二维表面位移／二维阈值侵蚀 | 能改善外轮廓；对主要在层下观看的薄云很有竞争力             | 同一 XY 的内部结构仍受单一柱约束；表面位移可继续使用柱积分，阈值侵蚀不能直接沿用原积分 |
| 高度相关二维采样           | 比贯穿柱纹更自由                                           | 仍有方向性约束；不能默认比一次 3D 采样便宜，且更难解析积分                             |
| 薄层包络加共享三维噪声侵蚀 | 地面、山顶斜视及转动太阳时，凹凸与自阴影有更一致的体积依据 | 必须处理采样频率、质量平均和光学厚度近似，不保证自动更锐利                             |
| 全套低云密度与步进         | 表达能力强                                                 | 会带入不必要的高度剖面、查询和步进成本；目前没有证据需要这样做                         |

**倾向把“薄层包络加共享三维噪声侵蚀”作为质量候选，把“二维表面侵蚀”作为同等认真比较的低成本候选。** 现有研究还不足以给两者做最终画质排序。明确不推荐只不断增加 wisp 强度，或直接把低云 marcher 复制一份。

若使用三维细节，应尝试替换现有细节作用而非不断叠加：使用一个已经打包多个频段的形状体查询，侵蚀薄层的轮廓；二维 cell 保留宏观云团作用。细节尺度用世界米制坐标控制，风锚定继续随中云，不能因复用低云纹理而改用低云的风、NDF 或演化坐标。

### 成本主要取决于查询被重复多少次

当前一个启用了全部细节且天气非空的柱查询包含：1 次天气、2 次 warp、1 次 cell、1 次 wisp，即 5 次二维纹理采样。一次有效视线样本加 8 次自阴影探针，在探针也非空时共有 45 次这类采样；这是源码调用计数，不含 LUT、环境光和散射计算，也不代表 GPU 时长。

如果每个位置直接加一次 3D 采样，会增加最多 9 次体纹理查询，而不是 1 次。反过来，用 3D 替换 wisp 也不能仅凭采样条数相同就宣称等成本，缓存、过滤、寄存器占用与步数都会影响结果。

对真正细碎的侵蚀，视线保留可分辨细节，光照可以读取其粗尺度有效密度／光学厚度；但这个近似必须计入侵蚀移除的质量。不能让视线已经挖空，阴影和中云供给低云的环境辐射仍按完整旧柱计算。宏观条带起伏则必须进入自阴影位置查询，不能被一个全局平均值替代。

新方案继续限定在独立上层 pass。成本评估要分别测低云 MainView、中云／高云 pass、上层太阳遮蔽和环境更新，另记合计。中云关闭时应核对低云采样工作是否回到无中云基线；中云开启的预算不能只看 MainView 名称下的计时。

## 光照独立于形态表示的具体含义

光照算法应读取位置相关的消光、光学厚度和边界辐射，而不是自己理解 cell、wisp、条带相位或某个噪声通道。不同形态可以提供这些量的精确值或经过验证的近似值，现有散射算法、世界锚定和中高云向低云供给环境光的关系保持一致。

这不意味着光照可以与形态无关。连续云幕的起伏会改变太阳光程；侵蚀会改变透射和供给低云的辐射。当前 [MiddleColumnDepths](<D:/lyj/codes/git/skyrim-community-shaders/features/Physical Sky/Shaders/PhysicalSky/MidCloud.hlsli:108>) 精确依赖柱状表示；更换表示时，其实现也必须同步适配，不能仅保留旧公式并称之为解耦。

## 下一步原型应回答的三个问题

1. **二维表面侵蚀是否已经够用？** 在当前资产、同等平均透射下，对比二维表面方案和单次共享 3D 查询方案，观察图 1、2 所需的内部小云团、云底和侧缘。分别看原始上层 pass 与时域结果，避免把重建模糊误判为形态问题。
2. **两类条带能否独立控制？** 固定太阳和相机，对照有缝条带与连续云幕；再旋转太阳与改变仰角，确认波纹的明暗来自光路。检查渐变天气下的覆盖和厚度是否平顺。
3. **新增结构是否值得其成本？** 在相同硬件、分辨率、云量和观看位置下记录各 pass 的 GPU 时间；同时检查移动视角、低太阳角和远景的稳定性。离线纹理计数和数值误差不能代替这一项。

这三个问题有结果后，才适合确定最终表示和默认参数。本轮的确定结论是：条带扩充可以继续使用二维天气载体；细节必须从整柱减密度扩展到轮廓；三维细节需要与其积分和粗尺度光学查询一同验证。

## 1.3.1：观测约束与截图问题复核

上一版解决了世界尺度和透天间隙，却把所有云带锁在同一条弯曲函数上。沿带方向取一维噪声、固定间距、八个波长的低通，使相邻条带只能同步弯曲。资料中出现过“局部弯曲、断开”的要求，但没有被实现及形态验收覆盖。解析积分测试通过不等于这个分布设计通过。

本次重新查看用户原图 3、4、5：图 3 有局部中断和宽度变化；图 4 是连续云幕中的非均匀起伏；图 5 的间隙有收窄、闭合，边缘另有更细的结构。照片未标定相机和云高，只用于这些形态约束，不能据此宣布某个米制尺度或概率分布符合气象统计。

- [WMO Ac undulatus](https://cloudatlas.wmo.int/en/varieties-altocumulus-undulatus-ac-un.html) 描述分离或合并、延长且大致平行的云块，也允许两组波纹；[Ac 说明](https://cloudatlas.wmo.int/en/explanatory-remarks-altocumulus.html) 描述云层分解成较规则的小元素。这支持“有组织但不要求全域等间距”的表示。
- [香港天文台](https://my.weather.gov.hk/en/education/weather/clouds/00102-stratocumulus-undulatus.html) 解释波动与凝结阈值共同形成云带和间隙，并指出中云有类似形态及机制。[NASA 的卫星案例](https://science.nasa.gov/earth/earth-observatory/the-undulations-of-wave-clouds-147380/) 显示局部气流可使波列中的云带消失。这些资料支持波形与局部成云条件分开表示，不能拿该海洋案例的尺度直接规定 As/Ac 参数。
- [Schmidt、Flatau、Yates（2014）](https://doi.org/10.1175/JAS-D-13-0172.1) 的高分辨率雷达案例发现亚公里尺度的 Ac 胞状结构。这支持条带内部还需独立细节，但不是所有中云的通用尺寸分布。

实现保留相位控制，同时做三项修正：二维连续位移让邻带具有不同的局部曲率和间距；局部天气及云块先改变成云裕量，再生成云带；湿端允许跨越波谷连成云幕，干端可以结束一条云带。最终 Billow/Wisp 仍独立塑形。既有世界坐标、上层风和低云 NDF 输入保持原约定。

弯曲场使用项目已有 PCG 哈希及五次插值，无新增纹理。横向四个、纵向两个波长的插值单元是数值设计，**不是观测统计**：在最大一个波长的位移下，横向相位导数下界为 `1 - 2 × 1.875 / 4 = 0.0625`，避免相位折返形成细长折叠。这个模型能表达局部有组织的波列和断续，但没有实现多组交叉波系，也没有声称复现全部 undulatus 分布。

另两个问题独立处理：

- 表面细密分层在关闭条带、云块和噪声的 GPU 对照中仍能复现。密度积分几乎一致，单点光照随段内空间质心的位置出现周期误差。改用视线衰减加权的光学质量位置，不增加视线或光照步数。16 段与 128 段的简化直接光对照，辐亮度 RMSE 从约 `0.0180` 降至 `0.0075`；去除缓变误差后的细密条纹 RMSE 从 `0.00190` 降至约 `0.00044`。这是离线场景，不是截图像素误差。
- 中云默认噪声纹理周期 1200 m，而低云水平周期约 230 m。新默认值为 256 m，保留已有自定义值。光照八段改为向表面集中，前两段查询局部噪声，远段仍复用过滤后的噪声。采用实际程序生成的形状体，与 1024 段密度参考比较，1200 m/256 m 的太阳透射 RMSE 分别由 `0.01343/0.02002` 降至 `0.01049/0.01433`。没有照搬低云的云底增密和高度云型规则。

实验与工作区快照位于 `build/middle-terrace`。当前条带过滤与密集数值参考的最大差约 `4.49e-6`；风平移、Weather Size 和输入 jitter 不改变固定世界场的验证通过。500 m/2000 m 间距的斜视透射 RMSE 约为 `0.01013/0.00116`。这些验证覆盖误差机制与一致性；仍需游戏内确认形态、时域观感及实际 GPU 时间。

成本没有保持不变。固定 4096 射线的中云光学内核，条带关闭约 `0.06346 → 0.08341 ms`，开启约 `0.07706 → 0.10389 ms`，分别增加约 31% 和 35%。这个核固定执行 16 段并使用合成输入，不是完整上层 pass，更不能换算成整帧耗时。低云 MainView 的 DXBC 指令部分与修改前逐字节相同。运行时根目录 include 规则下，MainView、上层视图、上层太阳遮蔽、环境边界和闪电合成五个入口均编译通过。

### 1.3.1 后续分层复核

后续截图仍有严重横向分层，所以上述简化直接光误差下降不能作为截图问题已解决的证据。它遗漏了实际的多重散射响应，也未充分覆盖接近水平的视线。补入生产代码的散射闭合与标定表后，在关闭条带、云块和侵蚀的 GPU 场景中复现了明显的等高线状明暗波纹。

确认的错误是把段平均消光系数同时作为光照点的局部材质密度。平均值包含段内空白；非线性多重散射使云表面相对步进网格的位置改变亮度。仅改为一个局部密度采样仍有偏差。修正采用衰减光学质量分布中的两点求积，分别计算局部散射再平均；段平均密度只用于视线消光。两点复用原有密度区间，光照射线仍为一次八段查询，光照公式和标定保持共用。

`build/middle-horizontal/verification.json` 记录了云层内及层上斜视、Billow/Wisp 和侵蚀开关的对照。无侵蚀的层上斜视辐亮度 RMSE 为 `0.02315 → 0.00534`；参考是 512 个视线区间，仍使用同一八段光照近似，并非完整高精度参考。透射率输出逐位不变。固定 512×512 射线的诊断内核约 `0.3960 → 0.4108 ms`（约增加 3.7%）；此数值不包含实际场景的大气、合成与历史重建，不能代替游戏耗时。低云 MainView、上层太阳遮蔽、环境边界和闪电合成的指令字节与修复前相同。尚未取得该截图的抓帧或游戏内修复结果。

### 局部剖面与噪声定义修正

此前用 1200 m 与低云约 230 m 的**纹理周期**直接论证缩小中云噪声，依据不充分。纹理周期、通道内部频率、重建权重、mip 和最终密度响应必须一起看。本轮没有继续修改周期；当前可调默认值仍为 256 m，不将它宣称为实测中云元素尺寸。

原始资料的两套噪声不能混用：Nubis Evolved 第 32–34 页及 Cubed 第 22–24 页回顾的是 Perlin-Worley/Worley 组合；Cubed 第 94、99、104 页的新体素噪声则以 RG 表示两档 Curly-Alligator Wisp，以 BA 表示两档 Alligator Billow。当前程序纹理是本项目的近似资产，默认基础频率 R/G/B/A 为 3/3/4/9，还有 octave 和非线性响应。因此 256 m 周期的基础格点间距约为 85/85/64/28 m，不能把整张纹理或单个格点直接称为最终云团大小。低云水平周期约 229.65 m、垂直周期约 287.08 m，也不是一个各向同性的“云团尺寸”。

物理约束来自 [WMO Ac 物理构成](https://cloudatlas.wmo.int/en/physical-constitution-altocumulus.html)、[As 物理构成](https://cloudatlas.wmo.int/en/physical-constitution-altostratus.html) 和 [Barrett 等的混合相 Ac 观测](https://acp.copernicus.org/articles/20/1921/2020/)。Ac 的液滴主体可有明确轮廓，也可能伴随冰晶和下垂结构；As 可以呈纤维、条纹或均匀云幕。Billow/Wisp 在这里是圆润与纤维形态的连续表示，不能直接解释为云属或水/冰比例。本轮保留已有 As/Ac 天气输入及其形态混合，也没有加入相态模拟或假定所有中云都有固定的液态/冰态分层。

实现修正如下：

- 最终侵蚀的 dimensional profile 改为**局部柱强度 × 采样高度的剖面**。普通噪声复用低云的 Billow/Wisp 重建函数，传入实际高度及相对观察距离；体素噪声复用 Cubed 通道重建。消光仍使用减法塑形结果，低云专用的底部增密及高度云型混合不移植到中云。
- mip 同时考虑局部剖面和像素 footprint。沿用低云 `profile * 3` 的内部降频依据，但使用连续 mip，避免薄层内部出现整数 mip 分界；没有再调整噪声周期、天气尺寸或条带尺寸。
- 删除“一个整柱侵蚀阈值”的视线积分。每个密度区间仍读取一次噪声，在未侵蚀剖面的质量坐标中用两个 Gauss 节点重建局部侵蚀比例，再对非负线性重建积分及求逆。噪声值在该区间内仍是冻结近似，**重建权重不再冻结为整柱值**。两个密度区间/视线步、八个自阴影区间的预算保留。
- 材质密度及光照位置从同一个重建积分求出，继续区分局部散射密度与段平均消光。环境光柱积分单独处理上下渐变边缘及内部，复用一个经过过滤的噪声值；上下光学厚度来自同一份累计质量。太阳遮蔽仍按空间位置查询，散射函数、标定及上层风锚定不变。

验证位于 `build/middle-local-profile`。实际程序噪声与随包体素噪声，在 256/1200 m 周期下与 2048 次逐点积分比较；加密密度区间后误差收敛。256 m、32 个区间的相对质量 RMSE 约为 2.9%/3.5%，64 个区间约为 1.3%/1.5%（体素/程序噪声）。这是固定柱、不同视角及 profile 的积分检查，既不代表画质提升比例，也不等于实际 marcher 的所有步长分布。

环境柱查询检查了 0.01、0.1、0.49 三档边缘宽度及两种噪声。相同过滤噪声下，对照 2048 次局部重建积分，默认边缘宽度的归一化 profile 绝对 RMSE 小于 0.00062；最宽边缘小于 0.00335。上下深度之和随查询高度的浮点差小于 1.2e-7。这个检查验证局部重建的积分近似，**没有证明先过滤噪声再侵蚀等价于平均真实密度**。

包含生产多重散射标定的层内场景中，相对 512 步参考的直接光辐亮度 RMSE，程序 Wisp 约 `0.00828 → 0.00679`，Billow 约 `0.00982 → 0.00836`。层上视角、二维切片及体素混合也通过有限值和收敛检查；层上环境项误差有小幅增加，不能称为所有分量都改善。关闭侵蚀时视线透射保持逐位一致。两种重建各自与其密集参考比较，不能把改变后的形态误认为同一密度场的纯数值修复。

最终检查使用正确的相机位置及大气基准高度转换。完成寄存器调整、隔离编译负载后，512² 诊断内核中位耗时约 `0.363 → 0.378 ms`，增加约 4.1%；编译后的上层 shader 静态纹理采样指令点仍为 62，临时寄存器从 58 增至 64。此内核不含完整生产大气和时域合成，不能代替游戏耗时。低云 MainView 的指令字节与部署基线一致。标准 hlslkit 配置没有覆盖本入口；补充三个 MainView 变体均成功生成字节码，基线和候选均有相同的 50 条既有 warning，严格零 warning 门槛没有通过。另用游戏的根目录 include 规则检查相关运行时入口。

本轮不据这些离线结果宣布原截图的条纹、模糊或闪烁已经解决；尚无游戏内画面及 GPU 抓帧确认。
